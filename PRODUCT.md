# FibreOps product context

## Register

product

## Users and purpose

Network operations engineers and technical demo audiences inspect a fibre-outage
response workflow. The console presents incident evidence, agent decisions,
integration results and voice controls. This is a reference demo, not a supported
network-management product.

## Existing identity

Operational, concise and evidence-led. Preserve the existing NOC console's system
fonts, slate surfaces and semantic status colours. Architecture documentation uses
the existing light service-diagram palette.

## Design principles

- Distinguish implemented behaviour, optional integrations and conceptual scenarios.
- Distinguish a successful service request from an accepted agent-quality result.
- Show conditional dispatch and on-demand voice as separate paths.
- Keep the animated architecture in documentation, not the deployed dashboard.
- Never present illustrative animation as live telemetry.

## Accessibility

Use semantic controls, visible focus and readable text. Motion must be optional,
pausable and respect reduced-motion preferences; step-by-step text must convey the
same information without animation. Avoid decorative movement and colour-only status.
