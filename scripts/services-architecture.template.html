Incident response

Read the workflow without animation
  1. Telemetry enters from the synthetic generator or a configured Event Hubs consumer. The orchestrator processes a signal.
  2. IncidentAnalysisAgent produces structured severity, probable cause and SOP references. Local knowledge and optional Foundry IQ provide grounding.
  3. NetOpsCoordinatorAgent coordinates ticket and notification tools. D365 is mocked; Teams delivers only when a webhook is configured, otherwise an outbox records the message.
  4. FieldDispatchAgent runs only when the handoff or configured severity policy warrants it. Tool results determine whether an engineer was actually assigned.
  5. Run records and traces are persisted; the console reads the results. Application Insights export is optional. A local rubric optimiser is separate from voice acceptance.
  6. On-demand voice uses browser audio, the authenticated console WebSocket proxy, and the pinned Foundry Voice Agents Preview version. Tools run on the server; credentials do not go to the browser.
  7. Stop response stops generation and queued playback, retaining the microphone. It cannot undo an external action already performed.
  8. Candidate voice acceptance collects synthetic spoken turns, scores them with the Evaluation SDK, and publishes gates to the latest Foundry portal. Passing text checks does not certify a native accent or activate a production version.
